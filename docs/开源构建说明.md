# 构建 BlueLedger

## 环境

- JDK 21。
- Android SDK Platform 37。使用 Android Studio 的 SDK Manager 或 `sdkmanager "platforms;android-37" "build-tools;37.0.0" "platform-tools"` 安装。
- Gradle Wrapper 9.8.0；插件和依赖版本锁定于 `gradle/libs.versions.toml`。

设置 `JAVA_HOME`，并通过 `ANDROID_HOME` 指定 SDK。也可在工程根目录创建仅本地使用的 `local.properties`：

```properties
sdk.dir=/your/path/to/Android/Sdk
```

`local.properties`、签名密钥、账本备份和构建产物均被 Git 忽略。

## 构建与测试

```bash
./gradlew :app:assembleDebug --console=plain
./gradlew :app:testDebugUnitTest --console=plain
./gradlew :app:lintRelease :app:assembleRelease --console=plain
```

Windows 将 `./gradlew` 替换为 `./gradlew.bat`。Android Studio 可直接打开工程根目录。首次构建需要联网下载 Wrapper、插件和依赖。

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`；未签名 Release APK 位于 `app/build/outputs/apk/release/app-release-unsigned.apk`。Release 开启 R8 与资源压缩。

项目未内置发布密钥或签名口令。使用 Android Studio 的 Generate Signed App Bundle / APK 或 Android SDK `apksigner`，通过自己的密钥签名。升级安装需要与已安装包使用同一签名；签名不同应先通过应用导出完整备份。

测试使用 JVM、Room 和 Robolectric，包括真实 Compose 页面交互。每个测试类使用独立 JVM、最大堆 3 GB；机器内存有限时可按测试包或类分批运行：

```bash
./gradlew :app:testDebugUnitTest --tests 'com.blueledger.app.feature.reference.*'
./gradlew :app:testDebugUnitTest --tests 'com.blueledger.app.feature.management.*'
```

仪器测试位于 `app/src/androidTest`，连接模拟器或 Android 设备后运行 `:app:connectedDebugAndroidTest`。不要在保存个人账本的设备上运行会修改数据的自动测试。

## 离线构建

先在联网环境完成依赖下载，再使用 `--offline`。若已经缓存 Compose 映射工具的 JAR，但缺少对应模块元数据，可使用仓库附带的限定版本辅助脚本：

```bash
./gradlew :app:assembleRelease --offline --init-script tools/offline-compose-mapping.init.gradle
```

该脚本只从当前 `GRADLE_USER_HOME` 查找已经缓存的构建工具 JAR，不包含绝对路径，不修改应用运行时依赖；缺少缓存时应联网构建，不能靠此脚本下载依赖。

## 自动构建与 Release

GitHub Actions 模板位于 `docs/ci/android.yml`，配置干净环境的 SDK 和 JDK、日期／分类／设置／固定目录专项测试、Release Lint 和 Release 构建。工作流产物中的 Release APK 未签名。

当前发布账号的 CLI 登录缺少 `workflow` 权限，因此尚未启用在线 CI。使用有对应权限的登录后，将模板放到 `.github/workflows/android.yml` 并提交即可启用；也可在 GitHub 网页编辑器中添加。首次运行结果应单独核对，不能用本地测试通过代替在线 CI 成功。

GitHub Release 的 1.1.3 APK 是经过本地验证的已签名安装包，沿用项目最初的开发证书。仓库不公开该证书的私钥。自行构建或 fork 发布时使用自己的证书。
